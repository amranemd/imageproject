# Multimodal RAG Image Captioning, Phase 1

Phase 1 of an image-captioning project built on retrieval (RAG) with MS-COCO 2017.
This phase prepares the data: exploration, cleaning, splitting, CLIP embeddings and a FAISS index.
The full analysis and interpretation are in [REPORT.md](REPORT.md).

## Results at a glance

| Item | Result |
|---|---|
| Knowledge base | 10,000 clean, unique images (seeded random sample of COCO train2017) with 50,024 human captions |
| Validation set | 100 images drawn from within the 10,000 |
| Test set | 100 images from COCO val2017, separate from the knowledge base |
| Images audited | 10,500 (0 missing, 0 corrupted, 0 duplicates found) |
| Embeddings | CLIP ViT-B/32, 512 dimensions, L2-normalised: 10,000 images, 50,024 captions, 100 test images |
| Index | FAISS `IndexFlatIP` (exact cosine search) for images and for captions |

## Method

1. **Cleaning.** A seeded random pool of 10,500 train images is audited for missing files, missing captions,
   corrupted images (the file must open and decode) and byte-identical duplicates (SHA-256, first copy kept).
   The first 10,000 valid, unique images form the knowledge base.
2. **Splitting.** Validation is a random subset of the knowledge base. The test set is a random sample from
   COCO val2017. The split report confirms there is no overlap and no byte-identical file shared between test
   and knowledge base.
3. **Exploration.** Statistics are computed on the 10,000 knowledge-base images only.
4. **Embeddings.** CLIP images and captions share one embedding space, so a query image can retrieve both
   similar images and relevant captions.
5. **Near-duplicate check.** CLIP cosine similarity of 0.95 or more is flagged, inside the knowledge base and
   between test images and the knowledge base. Flagged pairs are reported, not removed automatically.

## Design decisions and limitations

- Validation images stay in the knowledge base (the brief says they are drawn from within the 10,000).
  During validation, the query image itself must be excluded from retrieval, or it will find itself.
- Duplicate removal only catches byte-identical files. Resized or re-compressed copies are only flagged
  through CLIP similarity, using a 0.95 threshold chosen as a practical heuristic.
- Scene complexity is a simple proxy based on the number of annotated objects.
- COCO provides categories and bounding boxes, not attributes or relationships, so none are claimed.
- The image-to-caption check in `index_report.json` is a quick sanity test on 500 images, not a full evaluation.
- Embedding matrices and index files are not committed (the caption embeddings alone are about 100 MB).
  They are regenerated by `--step embed` and `--step index`.
- Caption generation, context augmentation and evaluation belong to later phases.
